# 设计说明 —— 《垃圾分类大作战》

## 1. 总体架构

```
data/trash.js ──▶ chart.js（谱面生成）
data/levels.js ─┘        │ notes（相对时间）
                         ▼
audio.js ─ startTime ▶ chart.attach（绑绝对时间）
   │                        │
   │ AudioContext.currentTime（唯一时间源 t）
   ▼                        ▼
judge.js ◀── input.js ◀── 键盘/鼠标/触屏
   │ onJudge
   ├──▶ effects.js（视觉反馈）
   ├──▶ ui.js（HUD / 弹窗 / 结算）
   └──▶ main.js（状态机，每帧 rAF 驱动 render.draw）
```

三层隔离（对应三个分支，互不干扰）：

- **core（甲）**：audio / chart / judge —— 纯逻辑，不碰 DOM 与 Canvas；
- **render（乙）**：render / effects / input —— 只读 state，禁止写游戏状态；
- **ui（丙）**：ui / storage / data / css —— 页面外壳与内容；main/index 由组长独占。

## 2. 核心设计决策

### 2.1 音画同步（音游成败关键）
不用 `performance.now()`（与音频输出漂移），统一用 `AudioContext.currentTime - startTime`。
暂停直接 `ctx.suspend()`：currentTime 冻结，恢复后 BGM 与谱面零漂移。

### 2.2 "分类"如何有意义（本作最关键的设计）
不做"4 轨道对应 4 桶"（那样按键与分类无关）。改为：垃圾随机横向落下，
玩家按**任意桶**，系统取"离判定线最近且未判定"的音符，比较**按的桶 vs 正确桶**：
- 桶对 + 时间准 → Perfect / Good；
- 桶对 + 时间偏 → Bad；
- **桶错 → 分类错误**：该音符失败、扣命、弹出知识点。
节奏手速与环保知识同时构成压力，这是选题亮点。

### 2.3 判定窗口（冻结）
| 条件 | 判定 | 分数 |
|---|---|---|
| ≤55ms | 完美 | 100×倍率 |
| ≤115ms | 良好 | 60×倍率 |
| ≤180ms | 勉强 | 30×倍率（断连击） |
| 超时 / 按错桶 | 漏接 / 分类错误 | 0，生命 -1 |

倍率：combo≥10 → ×1.2，≥25 → ×1.5。生命 3。

### 2.4 版权与可部署
BGM/音效全部 WebAudio 合成（鼓组 + 贝斯音序）；数据用 `.js` 而非 `.json`
（兼容 file:// 双击运行）；零构建直接静态托管。

## 4. 视觉规范

- 风格：**蓝白清爽浅色主题**（页面与画布均为浅色底），所有颜色引用 `css/base.css` 变量；
- 四分类色（冻结）：蓝 `--bin-0` / 红 `--bin-1` / 绿 `--bin-2` / 灰 `--bin-3`，与 `render.BIN_COLORS` 一致；
- 音符瓦片：**白底深字 + 中性灰描边**（不露分类色，避免泄题）；
- 判定线与节拍网格用蓝色 accent；判定反馈色：完美金 / 良好蓝 / 勉强灰 / 失误红（浅色底上均清晰可见）；
- 字体：system-ui + 微软雅黑，标题 46px、HUD 分数 28px、音符 17px。

## 5. 坐标常量（冻结）

逻辑分辨率 960×640；判定线 y=520；桶区 y=556、桶 190×76、间距 16、pad 56；
音符瓦片 124×44；下落公式 `y = JUDGE_Y - (hitTime - t) × level.speed`。
